* -- git add -- *
* git add <filename>        : add file to staging area.
* git add <file1> <file2>   : add multiple files to staging area
* git add -A                : Add all Changes ( Modified , Deleted , Untracked ) for Repository
* git add -all              : Add all Changes ( Modified , Deleted , Untracked )
* git add .                 : Only Untracked and modified File of Current Directory.
* git add -u                : Only stage modified and Deleted files of current Directory. ( not entire Repository )
* git add --update          : Only stage modified and Deleted files of current Directory. ( not entire Repository )
* git add -u :/             : all modified and deleted files in the entire repository will stage, regardless of where you are.
* git add --refresh         : Refreshes the index without adding any files. Updates metadata if needed.
* git add -f                : forces git to stage ingnored files ( .gitignore ) 

* -- git commit -- *
* git commit -m "Message"               : For commit   
* git commit -a -m "Message"            : direct commit modified and deleted files.
* git commit --amend --no-edit          : add current changes with last commit without changing commit message.
* git commit --amend -m "New Message"   : add current changes with last commit with updating commit message.
* git commit -C <Commit-hash>           : create a new commit with message of earlier commit
* git commit -c <Commit-hash>           : can reference the commit message and also can edit that.

* -- git restore -- *
* git restore file          : Discard the changes in working directory for file and get it to it's last commited state.
* git restore .             : Discard all changes in working directory
* git restore --staged file : unstage the file but keep changes  to the working directory
* git restore --staged .    : for unstage all files
* git restore --sorce=commit file   : restore file to the specific commit


* -- git merge -- *
A fast-forward merge occurs when the branch you're merging into (e.g., master) has no new commits since the branch you want to merge (e.g., feature) was created. In this case, Git simply moves the master branch pointer forward to the feature branch’s latest commit, without creating a merge commit.
A non-fast-forward merge occurs when both branches have commits that aren’t shared. In this case, Git will create a merge commit to combine the changes from both branches.


* git merge new_branch  : merge the branch to the current branch
* git merge --no-ff featuer : merge feature branch without fast forwarding to the master
* git merge --squash feature : combines all the commits from the feature branch into one single commit.
* git merge --abort : abort the merge ( if you encounter the merge conflicts )
